# ADR-0004：多标签工作区与命令入口

## 状态

Accepted

## 背景

界面原本是三栏（左对象树 / 中编辑器与结果 / 右驱动能力面板），且只有一个查询上下文：

- **一个查询文本、一份结果**。工作区顶部写死 `"查询 1 · {驱动名}"`，暗示了本来打算做
  多标签但没做。想比较两条查询，或者在写 SQL 的同时看一张表，只能来回覆盖。
- **双击表会覆盖当前编辑器**。查数据这个高频动作会丢掉正在写的查询。
- **一把全局锁**。`operation_busy` 同时管查询、执行计划、慢查询、导出、表加载和表提交。
  查询运行期间对象树不能展开、别的表不能加载、导出也点不动。
- **右侧常驻能力面板**占 190–360px，显示一张全天不变的表；用户真正会问的是
  「为什么这个按钮是灰的」。
- **没有键盘入口**。所有动作都要移到工具栏点击。

## 决策

### 1. 工作区改为多标签，每个标签页自带操作槽

`Tab` 持有查询文本、结果缓冲、分页、执行计划文本、表编辑器，以及自己的
`operation_busy` / 取消令牌 / 当前操作 id。一个标签页在跑长查询时，另一个照常工作。

### 2. 异步结果按标签页 id 投递

每个会产生结果的事件都带上发起它的 `TabId`。投递时用 `with_tab` 临时把该标签页设为
活动页再套用既有处理逻辑，之后还原。

这样做的理由是**只保留一条处理路径**：staleness 校验（会话代次 + 操作 id + 表编辑
revision）本来就写得很谨慎，为「非活动标签页」再写一份必然会漂移。id 找不到（标签页已
关闭）时结果直接丢弃。

### 3. 双击表新开标签页，重复打开则切回

打开表不再覆盖任何东西。同一张表已经开着时切回去，而不是重复开一个。

### 4. 驱动切换重置工作区，断开连接保留查询文本

切换驱动意味着查询语言变了，把 SQL 留在 Redis 标签页里只会误导，所以收敛成一个新标签页。
断开连接只让结果失效、丢掉表标签页，用户写的 SQL 保留。

### 5. 删除右侧面板，把能力信息下沉到按钮

「执行计划」「分析执行」「慢查询」在不可用时通过 `on_disabled_hover_text` 说明原因
（未连接 / 该驱动不提供 / 这个标签页正在执行）。答案出现在用户产生疑问的地方。

### 6. `Ctrl+K` 命令面板作为总入口

执行、切换标签页、打开表、载入已保存连接、回填历史、导出、解锁凭据库都在面板里，
按子序列匹配打分。工具栏因此只保留少数高频按钮，新增功能不必再抢工具栏空间。

### 7. 编辑器补全只用已加载的元数据

补全词典来自对象树已经取回的表名、列名和索引名，加上驱动语法的关键字。**补全不会触发
任何额外查询**——在生产库上按一次键就发一轮元数据请求是不可接受的。

## 后果

### 正面

- 长查询不再阻塞其它工作；对象树、导出、另一个标签页都能同时进行。
- 打开表不会毁掉正在写的查询。
- 结果不可能落到错误的标签页，且这一点有测试锁定。
- 屏幕横向多出 190–360px 给数据。
- 全部高频动作有键盘路径。

### 负面

- 内存随标签页数量线性增长：每个标签页各有一份有界结果缓冲（默认 10k 行 / 64 MiB）。
  预算目前是每标签页的，不是全局的。
- `with_tab` 会在事件投递期间临时改写 `active_tab`。这是刻意的取舍——换来单一处理路径
  ——但读代码时需要知道这件事，所以函数上写明了。
- 整个窗口仍然共用一个连接。多标签让「不同标签页连不同库」变得像是理所当然，但它还没实现。

### 中性

- `app` 模块拆成 `mod` / `events` / `views` / `commands` / `connections` / `tests`，
  单文件从 3640 行降到 1883 行。拆分沿职责切，不是按行数切。

## 备选方案

### 每个标签页保存/恢复状态，事件只作用于活动页

未采用。事件到达时活动页可能已经变了，结果会落到错误的标签页——这正是要解决的问题。

### 为非活动标签页单独写一套事件处理

未采用。会出现两份 staleness 校验逻辑，而这部分的正确性依赖细节，必然漂移。

### 保留右侧能力面板但默认折叠

未采用。折叠后它就只是一个没人展开的面板；把答案放到按钮提示里，信息才真正被读到。
